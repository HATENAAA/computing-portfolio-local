My contribution

The practicum report lists my responsibilities as frontend implementation, sourcing interface assets, and integrating content. The backend, database and doctor workflow are presented as team work.

Team system architecture

AreaOriginal implementation
Patient appAccount and profile, clinic and package browsing, dates, confirmation, appointments and reports.
Appointment servicesSpring Boot controllers connect the calendar, clinic, package and order services. The calendar reports configured capacity, booked counts and remaining slots.
Doctor and reporting servicesThe backend provides order lookup, check-item entry, detailed results and an overall result. The patient app reads reports by order ID.
PersistenceJPA repositories use MySQL. An order links the user, clinic, package and appointment date; report records reference the order.

Running application

The local edition uses the original patient app and backend, with a doctor workspace rebuilt from the practicum report and team APIs. Doctors can filter appointments by patient, package, date and report status, enter results and read archived reports. Both interfaces use fictional records.
